# Tavern courier-switch contract

`src/medieval/tavern-courier-switch.ts` owns contract v1 for the one currently implemented operated Jomon prop: voluntary perspective switching at `prop:task-ledger`.

## Authority and eligibility

The immutable household remains the only roster authority. `initialHouseholdActiveCrew()` supplies its canonical static eligible order and its bounded `{ id, name, role, conversation }` selection data. The tavern contract intersects that view with validated persistent-person life and availability, excludes the current active courier and any canonical permanent departure, and exposes no initial-world person seed, frontier commitment, history, equipment, persistent-person detail, inferred location, hidden fact, browser state, or copied/persisted roster.

The physical source is the existing deck-plan binding `deck-prop-binding:prop:task-ledger`: prop `prop:task-ledger`, ledger kind, tavern area, coordinate `4,4`. [`vessel-proximity-operation.ts`](../src/medieval/vessel-proximity-operation.ts) v1 is now the shared owner of validated canonical prop binding and exact-anchor occupancy; the tavern contract consumes its implemented-ledger result rather than independently deriving the binding. A transition is available only when navigation names the current active courier and that courier is exactly at that anchor. Away from it, or when no alternate eligible living available household member exists, the contract returns a bounded unavailable result. Malformed household, person, navigation, prop binding, provenance, replay, or world evidence fails closed.

## Zero-time transition

Initial selection and current perspective are separate mutable concepts:

- `state.courier.initialCourierId` is fixed by zero-time creation selection and remains creation provenance.
- `state.courier.activeCourierId` is the current inhabited courier used by navigation, movement, fidelity, autonomy, conversation, delegation, terminal status, and the tavern transition.

`switchTavernCourier()` validates the complete current world, runs the shared pure reducer, appends exactly one typed `tavern-courier-switched` causal command, and returns a new full envelope. It retains initial selection, sets active courier and navigation to the target at the ledger anchor, reconciles current-courier fidelity/autonomy projections at the same world minute, and updates only the task ledger's bounded latest-action record through that existing command. It does not advance world time or action sequence, draw randomness, alter immutable household/manifest/initial-world evidence, mutate unrelated people, create cargo or gameplay prop state, schedule simulation, or write storage itself.

Repeated selection of the active courier, unknown/noneligible/dead/unavailable targets, operations away from the anchor, missing initial selection, active/navigation mismatch, forged binding, malformed causal evidence, direct mutation, or replay mismatch are rejected without changing the submitted input. A currently active continuity successor must be living and non-departed but may remain committed or temporarily unavailable; targets remain strictly living and available. This task introduces no player-triggered loss, succession choice, recruitment, rest, conversation, cargo, trade, travel, or other prop operation.

## Presentation and persistence

Terminal presentation v13 derives one keyboard-first ledger prompt from the validated world: source, current courier, canonical candidate list, availability reason, semantic palette state, paired non-colour cue, accessibility text, and source/time/freshness evidence. At the exact anchor it also carries the compact physical availability/loss readout described in the continuity contract; away from the anchor it carries no such readout. The remappable contextual control opens it; Arrow keys select a bounded candidate, Enter confirms, and Escape cancels with no mutation or time change. The same control presents independent source-backed zero-time station readouts at every other exact static prop anchor, but those do not alter ledger eligibility or behavior. Normal status/messages retain the latest task-ledger action alongside any recorded station/cargo outcomes. The canvas only renders this validated projection and forwards typed intent. Detailed-renderer adapter v7 receives the same prompt/readout/feedback bundle but has no input, world, timer, persistence, or authority access.

`MedievalWorldState` v16 / courier v3 and causal replay projection v8 explicitly encode active courier, permanent departure exclusion, the bounded eight-record vessel-action projection, and separate bounded cargo lots. `FoundationWorld` v15 adds only fixed deterministic eight-prop provenance; `WorldDeckNavigationState` remains v1, the immutable manifest and generator/RNG streams are unchanged, and IndexedDB remains layout v4 with no store or migration. A valid v14/v13 or v14/v12 full envelope is upgraded read-only through the existing courier conversion, the strict validated v14 three-prop to v15 eight-prop conversion, the original-contract v15/state-v14 action bridge, and the original-contract v15/state-v15 cargo bridge. Reads never overwrite the old record; an explicit later save may write the current full envelope only after validating its old source/index. Corrupt or ambiguous input remains stored and unavailable.
