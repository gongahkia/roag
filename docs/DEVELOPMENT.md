# Roag development guidance

Read [PROJECT_STATE.md](PROJECT_STATE.md) before working. Update it alongside behavior, controls, saves, tooling, content or known limits; record actual checks in [VERIFICATION.md](VERIFICATION.md).

Roag is one fantasy party RPG, incorporating selected systems from Ithica's replayed history. Follow [INTEGRATION.md](INTEGRATION.md) for the user-approved direction and unresolved design choices. Adapt mechanics to Roag' lore and bindings. The pinned local Ithica reference is development-only; keep this game runnable with its own source, assets, catalog, mappings and project references, without asset symlinks, submodules or runtime paths into the reference checkout.

Keep graphics-free deterministic rules in Core and presentation/input in Client. Preserve invalid-action no-cost behavior, independent map/combat RNG, reachable quest prerequisites, persistent maps and exact saved continuation. Use `./roag.sh` to launch the game and `./dev` for developer tools. Both use `tools/dotnet.sh`; `tools/setup-dotnet.sh` provides the optional SDK installer.

Preserve original source images, IDs, crops, provenance and uncertain identities. Edit authoring inputs and regenerate derived catalogs. Historical `ithica-*` asset filenames/catalog fields, original pack names and `lantern-rpg` save identifiers are intentional origin/compatibility records; do not globally rename them. New saves belong under `~/.vagabonds/`, and legacy imports must leave their source untouched.

Preserve unrelated user changes and use cohesive commits when authorized. Keep build output, player saves and readable generated `assets/catalog.json` out of source control. Distinguish configured CI from executed checks and local graphical testing from untested platforms.

At every substantial milestone, review authoring/tooling usefulness. Each new content family needs stable IDs, validation, reference discovery, a reproducible preview/scenario and an updated authoring guide. Extend the shared developer entry point for repeated manual workflows, and use it against real game content. Data composes registered deterministic mechanics; new mechanics still need Core code, an explicit extension point and meaningful tests.

Use `./dev agent context` and `./dev agent impact` to orient and choose checks. For sustained tasks, persist explicit requirements/checkpoints and use `./dev agent verify --profile PROFILE --detach`; reconnect by run ID. Complete tasks only after fresh evidence covers their requested profiles/scenes and any visual review. Scenario files reproduce actual rule failures; validated content patches support safe iteration. See [AGENT_TOOLING.md](AGENT_TOOLING.md) for commands, limitations and examples.

For performance changes, use `./dev benchmark --seed 42 --samples 25 --output artifacts/core-before.json` for warmed Core query/routing/work timings and allocations. Repeat with the same seed/sample count after the change and compare `checksum` / `simulationHash` as well as timing. `./dev benchmark-render --output artifacts/render-before --no-build` measures stationary world/resource/combat scenes through isolated native clients; choose a new output directory for each run. Build first when using `--no-build`. Software rendering and load affect timings, so retain allocations and workload identity rather than enforcing machine-specific speed thresholds.

The reviewed paired measurements use `DOTNET_TieredCompilation=0 ./dev benchmark --seed 42 --samples 50 --output artifacts/core.json` for both builds, and `LP_NUM_THREADS=1 ./dev benchmark-render --output artifacts/render --no-build`. These settings stabilize the comparison; they are benchmark settings, not changed game defaults. See [PERFORMANCE_REVIEW.md](PERFORMANCE_REVIEW.md).

`./dev benchmark-streaming --seed 42 --samples 25 --output artifacts/streaming.json` compares synchronous terrain demand with adoption of completed background terrain across site floors, checking all terrain/biome/culture arrays, cache demand order and saved state. It explicitly waits for preparation and reports that cost separately. Its ready-hit timings do not establish that real travel always finishes preparation before demand; use native journeys and ordinary session recordings for that question. Streaming diagnostics include ready hits, failed/discarded requests and bounded queued/in-flight work. Background code owns its generator and never writes visibility, state, RNG or graphics resources; session replacement/shutdown disposes it without blocking on speculative work.

`./dev profile --kind all --live --seconds 15 --output artifacts/profile` collects managed stack/GC/runtime evidence and OpenGL capture/replay evidence on private displays. See [PROFILING.md](PROFILING.md) for pinned tools, setup and interpretation. Profiling changes timings; retain separate uninstrumented benchmark comparisons. Never launch captures/replays on the host desktop during unattended verification.

`./dev audit-simulation --seeds 42,1337,-42 --steps 7200 --output artifacts/body-audit.json` runs real world ticks against a full-cadence body reference. It compares complete state hashes and resource conservation through hunger, rest, foraging, non-hour expiry, near/far moves, live body/trait/life changes and an exact interrupted save. Reports include decision-visit counts and paired elapsed times; these are headless simulation measurements, not frame-rate estimates. The world verification profile retains this audit automatically.

Use `--steps 720000` for one hundred actual days, retaining day 7/30/60/90/100 growth checkpoints, the midpoint and final state. Schema two adds actual tick-call allocations, bounded timing histograms (p95/p99 upper bounds and >200ms stalls), retained actor/history/cache counts, economy/shortage observations and exact save/load at every growth checkpoint. Save sizes distinguish currently referenced data from all files under the temporary slot. Process memory/GC/allocation totals include both worlds and audit/report overhead; forced collections occur outside measured tick calls. They are not client-only memory or frame-rate measurements. Separate processes per seed permit independent GC/memory observations. These stationary-observer pipelines complement, rather than establish, crowded-work and streaming/floor-journey acceptance.

World saves prune unreferenced 64-hex-named JSON snapshots only within their own chunk directory, after atomic manifest replacement. A failed serialization/replacement cannot remove the previous manifest's chunks. Unrelated files and independent slots remain untouched. Cleanup IO/access failure emits `save-cleanup-failed` to the optional diagnostic sink and retries on a later save; the already committed save still succeeds. Save versions and current checksums are unchanged.

Reward receipts retain constant-time live hash-set lookup but serialize as a numerically ordered identity array. Reclamation removes old receipts, and a later hunt can reuse a hash-set slot differently across a reload; stable serialization preserves exact full-state comparisons. Legacy unsorted arrays remain valid and loading never rewrites the selected file. Preserve the real reclaim/reload/new-hunt and legacy-array regressions when changing receipt persistence.

`./dev audit-crowded-work --seed 42 --output artifacts/crowded-work.json` runs all 64 excavation orders with the maximum four-person party, twelve downed blockers, real output cargo/delivery, suspension/resumption and exact blocked/walking/work/hauling/completed reloads against full body cadence. The controlled arena, resting background roster, scripted gate/blocker removal and ample pack food isolate routing/work ownership; use separate normal-world runs for survival/balance. Every tick checks regional conservation and actual extracted stone. The world profile retains seed 42; Core tests exercise 42/1337/-42. All checks are headless and use temporary slots.

`./dev audit-ecology --seed 42 --steps 720000 --output artifacts/ecology.json` runs 7..100 actual days (50,400..720,000 ticks), beginning with seeded migration and continuing through actual hunts, births, retained remains and adjacent loot collection. The migrated population retains its origin/home; four uncollected historical individuals deliberately stop recovery for a real day before collection permits safe reclamation. Near/far/other-floor observer placements, exact saved phases, full-cadence state/accounting comparisons and growth snapshots cover this lifecycle. Initial pressure, cleared approaches, a resting background roster, strong hunter and ample pack food isolate ecology; the observer placements are fixture relocations and this is not natural unassisted population balance. Failure snapshots beside `--output` retain both complete states and the first differing field. The world profile and Core regression use seven actual days. The Core profile allows 600 seconds for the expanded elapsed-time tests; assertions are unchanged.

`./dev audit-travel --seed 42 --output artifacts/travel.json` walks the maximum four-person party through surface chunk crossings, all four floors and a deep chunk round trip. Prepared and synchronous worlds compare every demanded terrain/biome/culture array, demand/cache ordering, accounting and full state, including walking/floor reloads. Preparation receives ordinary view/movement predictions and is never awaited; fallback demand remains correct. Controlled clear corridors, parked route threats, preobserved ecology chunks and ample food isolate streaming. Core exercises three seeds and the world profile retains seed 42. Private native `world-streaming` uses actual mouse waypoints/stairs, checks separate drawn formation and cache/preparation limits, and requires prepared adoption during travel. Its mouse harness waits for interpolation before calculating click pixels. No test controls the host desktop.

`./dev preview journey --seed 42` exercises the same activated resident near the observer and after the observer leaves, requiring matching actor state, cardinal movement, actual food/rest arrival and exact offscreen saved continuation. It retains bounded route/terrain-read diagnostics. Use it alongside the full-cadence body audit when changing movement, needs, blocked-route retry or near/far activation. The private `world-routines` native scene checks the corresponding leave/reload/return path.

Activated residents seek another nearby habitat when local wild food cannot supply a two-food gather, including permanently cleared capacity-one ground. Searches reuse actual saved routine destinations, advisory two-food intentions and deterministic logical-tick rotation: at most four searchers and sixteen terrain probes each per tick, within ninety-six tiles. Actual arrival in the selected habitat precedes gathering; inspection/planning never creates food or discovery. `ResidentForaging` and diagnostic snapshots expose searches, terrain probes and retained request/claim counts. Keep the shared-stock competition regression, near/far and walking/gathering reload checks, and assigned-work ownership through food trips when changing this planner.

`./dev preview occupation --seed 42` executes real farmer, woodcutter, quarrier and healer extraction/hauling/crafting chains with conservation checks. `world-occupations` is the private native harvesting, saved ownership and home-delivery fixture. Activated workers must never also receive hourly aggregate production; joint cargo claims must cover both ordinary and player-directed jobs. Grain uses the established resource family and changes the content hash, requiring an explicit fresh slot. Never test compatibility by overwriting a real campaign.

`./dev preview habitat --seed 42` exercises shared finite forage stocks, no-cost exhausted rejection and elapsed recovery. `world-habitat` checks the corresponding Actions feedback, reload and actual waiting privately. Habitat views must remain pure and generate no terrain; explicit consumption/clearing/hunting settle saved food/pressure in hourly epochs. Compare recovery band boundaries against a sequential reference and preserve exact saved continuation alongside the full-cadence body audit. Resource-node stocks and aggregate settlement production remain distinct from the wild-forage budget.

`./dev preview migration --seed 42` exercises a real seeded animal finding and walking to a new natural home. Keep search work globally bounded, source/natal identity and carried goods intact, destination reservations unique and shared routes consistent with migration targets. Test near/far arrival and saves during both searching and travel. Private `world-migration` uses the actual Wait action for elapsed travel, then returns the observer on a recorded walkable route cell; arbitrary offsets can be solid and should be rejected by formation validation. Migration must not discover terrain or create another animal at its destination. Population recovery is described below.

`./dev preview recovery --seed 42` runs a real hunt and three days of actual world ticks, checking distinct identity, original remains, recovery budget and regional conservation. Private `world-recovery` uses an explicitly near-deadline clock fixture; do not describe it as a long-duration balance test. Population recovery must follow the migrated individual, spend actual wild food and preserve one-time rewards. Reclaim only taken/unreferenced dead metadata, account residual cargo loss and retain provenance; if references or uncollected remains fill the bounded history, delay recovery. Keep a per-call allocation control when changing warm cache probes. Exact pending/recovery saves should also compare scheduled bodies with full-cadence bodies.

`./dev preview consequences --seed 42` exercises actual completed source damage, food delivery, started-occupation interruption and victory over a witnessed threat. Private `world-memories` checks contextual harm/relief speech, refused/reopened recruitment and exact mouse reload. Consequences must follow original requester identities and real effects, retain cooldowns despite ordinary memory eviction, and leave automatic need/danger/invalid-source interruptions unblamed. Keep inspection/dialogue pure and preserve no-cost rejected assignments and recruitment. No authored content/hash change is needed for these registered event hooks.

`./dev preview weather --seed 42` uses real camp construction, walked resident home cover, exposed/covered steps, gathering and actual ticks through a weather change with conservation. Private `world-weather` uses an explicit near-change clock fixture after the same real setup; it is presentation/save acceptance rather than a balance claim. Check scheduled/full-cadence rest at a weather boundary and after camp edits, actual near/far shelter journeys, latched and legacy recovery timers, bounded elapsed habitat recovery and zero-allocation warm weather/cover queries. Resource recovery metadata belongs to its exhaustion event; later inspection/weather must not move that deadline.
