# Room expansion review

Open [review.html](review.html) directly, or serve this directory and visit
`/review.html`. For example: `http-server docs/room-review`.

The **New proposals** tab contains 15 room families. Each family has one
authored variant for each of the seven playable biomes: **105 distinct wall
layouts in 15 sizes**. A vote or comment on a family applies to all seven variants;
change **Preview biome** to inspect each one before deciding. The sprite-pack
selector works in both tabs. Five corridor topology and sidequest concepts have
their own group votes. The **Existing rooms** tab retains the earlier individual
room reviews and their saved feedback.

These are **review-only** records generated by `tools/room_prototypes.py` and
embedded by `make room-review`. They are not registered in `src/rooms.lua`, and
the corridor or quest concepts do not currently run in the game. Exported JSON
keeps the existing room feedback fields and adds `proposals` plus a separate
`proposal_fingerprint`. Older room feedback files still import.

The size mix ranges from a 9×13 watchtower and a 23×7 long gallery to a
23×17 fan arena. Start, combat, treasure, and elite pools all gain candidates.
The cloister, courtyard, and mosaic can serve landmark themes while also
fitting a combat or treasure slot in the current two-floor planner. Corridor
concepts cover a spur, rejoining braid, switchback, multi-arm hub, and false
end with a concealed loop. The accompanying quest sketches use clues, keys,
plates, braziers, and optional encounters to give those branches a purpose.

## What the preview represents

- The 15 families have different dimensions and cover. Each biome variant
  changes both the wall layout and hazard tiles. The 105 layouts are grouped
  into 15 related silhouettes rather than 105 unrelated room concepts.
- Each proposed room has three optional structure slots. The pictured prop is
  an example; no prop is placed in the live game by this proposal. The room
  stays connected even if all three slots later receive blocking props.
- Enemy and chest markers are candidate points. The current generator chooses
  only some candidates; the preview deliberately shows every candidate.
- The current two-floor planner does not assign a standalone `landmark` role.
  Landmark-focused proposals also carry a combat or treasure role so they can
  enter its current selection pools once approved and registered.
- Corridor diagrams describe possible branches, loops, and optional quest
  nodes. Their percentages are suggested upper bounds for suitable corridor
  links, not measured runtime frequencies. Sidequest rewards, gates, keys,
  plates, and clues still need game rules, persistence, and generation checks.

## Validation and integration notes

`python3 -m tests.room_prototype_tests` checks the 105 room templates against
the game's `Rooms.validate` contract, then temporarily registers them in
memory and validates 100 generated seed pairs in each of the seven biomes. It
samples all 105 layouts with no fallbacks or repairs in that corpus. It does
not write to the live room registry. `node tests/room_review_page_test.js`
checks the offline page data, initial proposal view, biome switch, tabs, and
group feedback storage without opening a browser window.

After review, integrating approved designs will require explicit room pool
weights, corridor placement rules that respect room footprints and traversal,
and sidequest state and reward rules. The generator currently lays out rooms
on a bounded grid and expects four clear room sockets. That constraint is why
these draft rooms use the existing supported size range and socket contract.
