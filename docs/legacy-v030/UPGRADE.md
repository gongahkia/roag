# Upgrade 0.2.0 -> 0.3.0

This update is based on the exact 0.2.0 source supplied in the earlier project ZIP,
not a scan of your local computer. Local edits must be merged rather than overwritten.

## Recommended route

1. Close the running game. Keep a copy of the old source directory.
2. Back up the whole LÖVE save directory for identity `deepward_02`, particularly
   `run.dat` and `archives/`. F6 in the existing game reports its location.
3. Extract the complete 0.3.0 ZIP into a DIFFERENT source directory. Do not overwrite
   or delete the save directory. Run `love .` in the extracted `deepward/` directory.
4. It intentionally uses the same save identity. Your readable 0.2 run should resume.
   Its terrain is unchanged. F10 runs the regression suites in your actual runtime.
5. Press N to preview the frontier maps. Escape preserves the current run. Confirming
   a displayed preview archives the old live replay and saves the new expedition.

Do not run both versions concurrently: they share the same save identity. Do not
assume an older executable supports saves written after installing this update.
For independent experiments, change `t.identity` in a separately copied project's
`conf.lua` to a different name before launching it; that uses a distinct save folder.

The code tolerates a reported write failure and leaves the old live world selected,
but this is not a transactionally durable database. Keep your backup.

## Copy/paste or update archive

`UPDATE_MANIFEST.md` identifies new/replaced files and important unchanged modules.
The update ZIP contains those complete files under `deepward/`; merge its contents
into a COPY of the old project. The complete source guide also contains file-by-file
text, including fixtures and example maps, so no omitted helper is required.

Do not paste only `main.lua`: the new generation, map, JSON, renderer and test modules
are required together. No original source file must be deleted for this upgrade.

## Three different versions

- Application: **0.3.0** (UI, generation, export tools).
- Colony save/state schema: **0.2.0** (compatible authoritative simulation fields).
- Terrain-template schema: **deepward-map / 1** (exact spatial input, no colony state).
- Current frontier recipe: **frontier-v1** (optional map-generation provenance).

A seed alone is not a preserved map. A map template is not a savegame. A generator
recipe version is not a promise that every future executable can regenerate it.

The test fixture in `tests/data/legacy-v020.dw` was generated by the untouched old
code and checked after 80 more ticks against its original expected state hash. That
validates this path. It does not establish compatibility with modified local rules,
corrupted saves, old top-down Terrain Lab files, or all possible historical versions.

## Expected differences

The existing colony can continue unchanged. A NEW frontier expedition uses a centred
arrival, richer surrounding geology, and 256x160 default dimensions rather than
192x112. Old cistern/dunes/frost generators and old mechanics remain available.
New terrain is not injected into a running expedition. No dead settlers are revived.
