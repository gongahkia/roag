# ROEG — Tranche 08 Save & Resume

ROEG is a LÖVE 11.5 roguelike prototype. `love .` opens a title screen for a new or saved run; a new run enters a seeded, continuous procedural Overgrown Ruins stage with fog, secrets, a Thorn Warden elite and a timed extraction route. `docs/ROEG_SPEC_v1.0.md` is the authoritative design baseline. The authored 15×11 foundation and 35×25 combat demo remain available by their explicit map IDs to headless tests and GUI fixtures.

## Run and controls

Run `love .`. The title offers **C/Enter Continue**, **N New Run**, and **Q/Esc Quit**. New Run asks for confirmation before replacing a resumable or incompatible active save. During normal gameplay **Esc** opens a pause menu: **1/Enter/Esc Resume**, **2/S Save & Quit**. Esc still cancels aiming, chest and route menus first. Saving, loading and pausing cost no world time or RNG. Save & Quit writes the latest stable player-ready state and exits only after the save is read back successfully; a failed write leaves the game open. A mid-animation save resumes with clean presentation because all authoritative effects have already resolved. Milestone autosaves follow chest claims, elite defeat, pursuer arrival, stage transition, death and the prototype endpoint. Hard termination resumes from the latest verified milestone; it may lose actions since then. The game does not save every frame.

LÖVE writes two rotating `active-a.roeg` / `active-b.roeg` records inside its platform save directory under the stable `roeg-foundation` identity. Each record stores a generation, snapshot/content compatibility IDs, payload size and checksum. The next generation is written to the inactive slot and read back; startup chooses the newest integrity-valid generation, falling back one generation if a slot is corrupt. A valid newer incompatible save is reported instead of silently loading an older run. Confirmed New Run replacement writes the inactive slot first and verifies it before replacing the older slot; if the second write fails, the game warns that only one new generation is verified, and the next checkpoint replenishes the backup. The codec is inert, length-prefixed plain data: it never evaluates save text. No hardware power-loss fsync guarantee or cross-version migration is claimed. Terminal/dead runs write verified non-resumable tombstones to both slots, so one damaged terminal slot does not revive an older active backup. Permanent unlocks, when implemented, will use separate storage.

The HUD shows the current stage and seed; the arena location appears only after exploration reaches it. **N** proposes restarting the same root seed and **M** proposes the next seed; normal play requires confirmation before either reset replaces the saved run. **Tab** shows/hides the discovered map without spending world time or RNG. `Game.new_stage(seed)` reproduces a normal first stage; `Game.new_generated(seed)` remains a stage-free fixture constructor for existing tests. Move with WASD/arrows; Space or `.` waits. Press **F** for Sword Strike, **R** for Sweeping Slash, or **X** for Dash; aim with WASD/arrows or Q/E/Z/C, then Enter. Escape cancels. Cardinal bump attacks, doors and chests use ordinary movement. After defeating the Warden, bump the cyan exit to preview two routes; **1/2**, Enter and Escape select, confirm and cancel. Routes reuse the Overgrown Ruins generator as explicitly labeled prototypes. A third stage exit shows the final-boss-pending endpoint.

**Explore:** Sight reaches eight tiles on the logical grid. Walls and closed doors block vision; unseen tiles show no known geometry, and previously seen tiles remain dimly remembered. Enemies, drops, chests and telegraphs appear only where currently visible. The minimap uses the same explored state and never shows undiscovered branches. Enemies continue acting outside the player's view. FOV updates at simulation decision boundaries, not each render frame.

**Discover:** Each generated floor places two optional secrets in transformed branch rooms. A thin diagonal moss crack on a wall means an explicit Sword Strike into that wall can open a tiny alcove with a cached free boon chest. A small moss spiral on the floor releases four currency when stepped on; the pattern fades after activation. These are consistent clues at variable seeded locations. Attack misses still cost normal time. There is no inspect/search key, and neither secret is required to reach the arena. A closed brown ruin door sits at an optional branch socket: bump it once to open for one normal movement recovery, then move into its tile. It blocks sight and projectiles while closed. Opening it never shifts a room or loads another screen.

**Earned rewards:** Kill enemies, then step onto their yellow currency drops. Five paid chests are spread across the generated floor. A cardinal move into a closed chest opens its three cached boon offers for free. Choose with 1/2/3 and press Enter to claim; Escape cancels without spending currency or world time. A claim costs five currency and one 100-base-time recovery. The claimed chest can be walked through. The chest menu blocks movement and attacks while open. Guard/Thornspitter/Skitter drops are 4/3/2 currency. A fresh run starts with no boons; there is no guarantee of enough initial currency to buy every chest.

**Developer showcase:** Press **B** while idle to cycle None → Lightning → Cascade → Transformation → None. This changes the test loadout without advancing world time; it is a debugging control, not the earned acquisition path. **N** restarts with the selected showcase loadout. The sidebar lists each equipped boon with C/U/R/L rarity stack counts. Lightning supplies Storm Conductor and Static Footsteps; Cascade supplies Storm Conductor, Detonation Bloom, Resonant Wounds and Temporal Echo; Transformation supplies Crescent Reach, Thorn Mirror and Turncoat Spark. Headless callers can use `Game.set_boon_stacks(state, owner_id, boon_id, rarity, count)` at a stable decision boundary, including zero to remove a rarity stack.

The generated floor places all three existing enemy archetypes across rooms and selected corridor alcoves. The reserved elite arena is shown with a purple floor and gold ring; **there is no elite enemy or exit yet**. The old authored demo remains `Game.new(seed, "core:map/scrolling_room", {demo_enemies=true,demo_chests=true})`. The sidebar shows player HP, level/XP, currency, combat stats, world time, last action/cost, historical playback, live windups and pending echoes. Level-up notifications are brief and do not block input. Death ends the run; N restarts its seed.

## Generated floor contract

`src/rooms.lua` contains validated plain-data biome rules (room count, dimensions, chest target, retry budget and existing enemy pool) plus six human-editable room templates: 9×7 entry/watch/shrine, 15×11 gallery/cache, and a 23×17 reserved arena. Templates declare stable IDs, roles, four facing sockets, secret approach/wall markers, allowed rotations/mirroring, and interior editable cells. All other authored room cells are protected. Transforming a room rotates/mirrors tiles, sockets, facings, markers, and editable masks together. No editor or elaborate puzzle is active in this tranche.

`src/generation.lua` plans a seeded 8–12 node room graph first. It connects a guaranteed start-to-arena route, attaches branches, then adds at least one loop edge. Selected transformed rooms occupy separated slots on a 140×90 tile grid; sockets connect through straight and dogleg corridors, with side alcoves on longer passages. Controlled variation opens some explicitly editable pillar/partition cells. Room footprints and protected authored geometry are never carved by corridors. The floor records concrete collision rows, a separate visual layer for stone/moss/corridor/arena, graph/room/corridor geometry, spawn and chest placements, elite marker, seed, attempt, and diagnostics.

Generation validates the **actual cardinally traversable tiles**, sockets, protected mask, graph loop/connectivity, start safety, room clearance, unique placement IDs, reachable arena, chest approaches, two optional secret clue approaches, their intact hidden wall/cache geometry, and an approach to the optional door. A blocked editable corridor cell or damaged clue visual can be repaired locally and is revalidated; protected faults remain untouched. Two deterministic retries follow an unrepaired failure; a known-reference candidate is independently validated as fallback and flagged in diagnostics. Seeded test faults exercise repair and fallback. The visual layer adds moss, vines and scattered rubble without changing collision.

`state.generated_map` is the authoritative concrete map for generated runs; the authored content registry remains unchanged for fixture maps. Movement, AI BFS, ranged blocking, Dash, targeting, FOV and rendering all use `Content.map_for(state)`. The saved run stores concrete geometry, revealed passages, explored cells, secret and door states, cached offers and runtime entities; restore validates and uses that map without regeneration. Snapshot schema is `roeg-run/7`, content version `roeg-content/6`, and exploration content version `roeg-world/1`; older snapshots require a fresh run.

Generation uses `RNG.derive(run_seed, floor_id + attempt)` and never consumes the combat/progression RNG. Generated chest offers each use a stream derived from the run seed, floor identity, and stable chest marker ID; offers are cached once. Adding decoration or another generated chest therefore does not change crit/stat rolls in an otherwise controlled combat sequence. Legacy authored-map chest RNG behavior stays as before.

## Provisional combat and timing

| Actor | HP | Damage | Defense | Speed | Windup | Recovery | Movement cost | Range |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| Adventurer | 24 | 4 Sword / 3 Sweep | 0 | 100 | Immediate | 100 Sword, 150 Sweep | 100 | Adjacent |
| Mossbound Guard | 10 | 3 | 1 | 70 | 80 | 120 | 100 | Cardinal adjacent |
| Thornspitter | 6 | 2 | 0 | 90 | 90 | 130 | 100 | Cardinal lane, 2–7 |
| Ruin Skitter | 4 | 1 | 0 | 160 | 35 | 70 | 100 | Adjacent, prefers diagonal flank |

These numbers are in `src/content.lua` and are provisional. Dash costs 130. Effective time is `max(1, round(base × 100 / speed))`, calculated with integer inputs. Damage is `max(0, attack damage − defense)`, capped at remaining HP. Direct Adventurer Sword and Sweep attacks roll the seeded crit chance once per attack; a crit rounds `raw damage × crit damage percent / 100` before defense and HP caps. Starting chance is zero, multiplier 150%; boon secondary damage does not crit automatically. Player strikes resolve immediately; enemies lock their target cells when a windup begins. An enemy has **no ready turn during its windup**. Its next ready time is impact time plus effective recovery. Ordinary damage does not cancel the locked strike; stun, displacement and death do. `Game.stun` cancels a windup and makes the enemy ready no earlier than the supplied integer stun expiry; `Game.displace` cancels it and applies one normal recovery before the enemy is ready again. A ranged shot stops at the first combatant in its locked lane, including an allied enemy. Terrain walls block firing lanes.

Sweep retains its provisional three-cell counterclockwise/center/clockwise order. All hit HP changes in an area attack are applied as one batch before `DamageBatchResolved` and individual `DamageAttempted`, `DamageTaken` or `DamageBlocked`, and `Died` records. `DamageTaken` requires positive actual HP loss. `HitConfirmed`, `EntityKilled`, and `TileEntered` are now emitted in boon-free runs too. Each actual enemy death yields one `EntityKilled`, one currency drop, and player XP only if the final damage source is the player (including a player-owned boon or delayed effect). Enemy-only friendly-fire kills yield no player XP. Events retain causal and spatial facts for downstream rewards and boons.

## Provisional progression and chests

Enemies grant Guard/Thornspitter/Skitter XP of 5/4/3. Cumulative level thresholds are 5, 15, 30, 50, then continue by an extra five XP per interval. Every crossed threshold automatically chooses one of six equally weighted stats through the saved simulation RNG: max HP +4, Sword and Sweep damage +1, defense +1, speed +10, crit chance +5 percentage points, or crit damage +25 percentage points. Max HP growth adds the same absolute amount to current HP; it does not refill missing health. An upgrade never changes recovery already committed. The HUD reports total XP and the next cumulative threshold. All parameters and weights live in `src/content.lua`.

Standard chests cost five currency and roll each of three **distinct boon identities** once, with independently rolled Common/Uncommon/Rare/Legendary weights 70/25/4/1. The same boon may be offered by separate chests and stacks by rarity. `Game.spawn_chest(state, "core:chest/free_elite", x, y)` supplies a reusable zero-price elite reward chest with 20/45/28/7 rarity weights; no elite enemy is added here. Offers are cached in the chest's plain-data entity before interaction, so Escape, reopening, and restore do not reroll them. The committed claim validates adjacency, funds, choice, and boon compatibility before one debit, one stack grant, one claim flag, and one effective 100-base recovery. `Game.chest_options` reads a copy of offers at a player decision boundary.

At equal simulated time, committed impacts resolve before newly ready actors. The player acts before newly ready enemies, then remaining actor ties use stable schedule sequence/ID order. A fast enemy can strike before the player is ready again; no reaction turn is inserted. Guard uses cardinal BFS around walls, Thornspitter seeks a clear lane and repositions, and Skitter seeks a diagonal flank. AI decisions use only simulation state and stable neighbor order.

## Presentation and architecture

`src/game.lua` owns combat state, action validation, damage, occupancy, interruptions, events, and snapshot/restore. `src/rewards.lua` consumes canonical kill events for XP/drops, collects drops on movement, and handles chest offer generation/claims. `src/ai.lua` chooses read-only enemy intents. `src/scheduler.lua` orders actor readiness and committed impacts. `src/targeting.lua` keeps Adventurer attack shapes. `src/content.lua` keeps authored maps/tile properties and tunable combat/reward definitions. `src/rng.lua` owns serializable gameplay RNG and stable stream derivation. None of these simulation modules references LÖVE.

`main.lua` renders only camera-visible generated tiles plus combatants, HP and locked tiles. `src/camera.lua` follows smoothly without affecting world time. `src/playback.lua` consumes **copies of already resolved ordered events** for short visual stages, including boon activations, secondary damage and delayed resolution. During playback, input is briefly gated; orange/red historical telegraphs are labeled as past events. When input is available, red highlights and the sidebar show only **currently pending authoritative strikes** and their simulated time to impact. Presentation state is never included in a simulation snapshot.

`src/visibility.lua` computes deterministic radius-eight wall/door-occluded FOV and per-floor explored memory. `src/world.lua` holds plain-data secret definitions and consumes canonical `AttackPerformed`/`TileEntered` events after the primary damage batch. It opens the wall/cache and creates a free chest, or creates and immediately collects the movement cache's normal currency drop. Secret placement uses a derived seed stream; the free chest uses its own stable marker offer stream. The `World.on_event` subscription seam also recognizes a future `ItemUsed` event shape (`source_id`, `item_id`, `target_position`, `action_id`); no item inventory or item action exists yet.

## Boon resolution contract

`src/boon_content.lua` contains eight validated definitions with four rarity parameter rows each. `src/boons.lua` indexes subscriptions by event kind, matches composable AND/OR/NOT and identity/tag/faction/damage/spatial predicates, aggregates stacks, and selects activations using the saved simulation RNG. Inventory is one plain table per owner: `boon_id -> rarity -> count`. There is no copy or inventory cap. Storm Conductor uses 2/6/18/50% per Common/Uncommon/Rare/Legendary copy; chances add and overflow into guaranteed plus fractional activations. Proc coefficients are declared on ability/effect content (default 1), validated, and multiply only probability-based activations. Other boon powers add across rarity stacks.

The eight prototypes are Storm Conductor (hit lightning), Detonation Bloom (credited-kill explosion), Thorn Mirror (positive-damage retaliation), Static Footsteps (move lightning), Resonant Wounds (two distinct hostile damage targets adjacent in one chain), Temporal Echo (locked repeat damage after 200 simulated time), Crescent Reach (Slash gains a forward cell and additive damage), and Turncoat Spark (observed enemy friendly-fire retaliation). Current provisional powers by rarity are 1/2/3/4; area radius is one tile. Static Footsteps chances are 5/15/35/70%. Observation radius uses Manhattan distance; Resonant Wounds and Turncoat Spark observe within eight tiles, Storm lightning selects a second hostile within six tiles, and Static Footsteps selects within two. Resonant adjacency and area centers use captured damage-event positions; area damage checks current occupancy. Pair identities are deduplicated per chain. Crescent Reach's forward cell requires an open middle and destination tile, so it cannot reach through a wall.

The game queues emitted events and effects iteratively after each primary damage batch and before the next scheduled actor decision. `AttackPerformed` can describe a miss; `HitConfirmed` requires contact, `DamageTaken` requires positive HP loss, and `EntityKilled` accompanies every actual death. `TileEntered` records each committed tile entry, including both cells of a full Dash. These factual events do not depend on owned boons. Existing exact-array tests were updated for the additional stable events while retaining their behavioral assertions. Events capture source/target faction, definition tags, positions, action/chain IDs, parent ID, coefficient and branch ancestry. Secondary damage uses the same HP, death, friendly-fire and ordered event pipeline. A boon may recur in sibling branches but cannot reactivate on a branch already containing its owner/boon key. One million resolution steps is a diagnostic error, not a silent effect cap.

Scheduled echoes use `src/scheduler.lua`'s committed-effect priority: they resolve before ready actors at the same timestamp. They retain locked target cells, attribution, chain ID and ancestry. The in-memory snapshot includes the generated concrete map and diagnostics, level/XP, currency, drops, chests with cached offers, player stats, inventory, delayed payloads, RNG and scheduler state. Older snapshots are rejected. Ability modifiers are reapplied in stable boon and declared modifier order from inventory without mutating `src/targeting.lua`'s base patterns. Cross-version save migration remains out of scope.

`Game.stun` and `Game.displace` remain the small simulation operations for interruption; there is no player stun/knockback ability or status-effect framework.

## Tranche 07 stage rules (provisional)

Normal `love .` uses `Game.new_stage`; older generated-map fixtures use `Game.new_generated` without a stage director. The Warden waits in the reserved arena until the player comes within seven cardinal tiles. Its three-cell Thorn Sweep and locked cardinal Root Line alternate when both are available. Below 50% HP it enters phase two and gains 25 speed for future commitments. Existing stun, displacement, death, friendly fire, and boon damage work through the combat resolver.

Before elite death, the pressure director first checks at world time 1,200 and then at 1,200/900/650-unit intervals as successful reinforcement count grows. It uses a separate seeded RNG, unseen reachable room anchors, an eight-tile player exclusion radius and an 18-normal-enemy cap. There are no frame-time spawns. Elite death produces one free enhanced-rarity three-offer chest and unlocks one exit. A 1,500-unit simulated-time grace period begins at the actual death timestamp; when due, one immune pursuer spawns at a distant unseen reachable point. The pursuer uses normal navigation, a locked adjacent strike and the scheduler; attacks against it produce blocked-damage feedback but no positive damage, kill reward or hit proc. The exit remains usable during pursuit.

Exit menus cost no world time. Route confirmation is an atomic **zero-time** stage handoff; the next generated stage retains player HP, stats, XP, currency, boons and gameplay RNG while stage-local actors, attacks, echoes, pressure and fog are retired in a frozen plain-data record. Later stages receive distinct floor instance IDs and route-derived seeds. Stages 2 and 3 deliberately use the same Overgrown Ruins generator; the third exit is a non-victory prototype endpoint. Snapshot schema `roeg-run/7` stores active stage state and frozen retired stages. Persistence envelope `roeg-save/1` serializes that existing snapshot without regenerating the floor.
